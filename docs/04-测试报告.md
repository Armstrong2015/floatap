## 3. 调度模拟

模拟器和真机都没有，所以用与运行服务相同的顺序做了时钟模拟：先倒计时，每一步先等待，再检查停止条件，然后记一次点击。时钟没有抖动。

### 3.1 单点 10 秒

配置：倒计时 3 秒，间隔 500 毫秒，持续时长 10 秒。持续时长从第一次点击起算。

| 项 | 模拟结果 |
| --- | --- |
| 停止原因 | 持续时长 |
| 点击次数 | 20 |
| 第一次点击 | 第 3500 毫秒（倒计时 3000 + 第一次等待 500） |
| 最后一次点击 | 第 13000 毫秒 |
| 相邻点击间隔 | 全部是 500 毫秒 |

需求里的验收范围是 18–21 次，用来容纳真机倒计时误差。精确时钟下是 20 次，落在这个范围里。真机还会多出系统调度误差，这次没有测到。

### 3.2 次数上限

倒计时 0，间隔 500 毫秒，上限 10 次。模拟在第 10 次点击后停止，没有第 11 次。

### 3.3 顺序循环

三步等待 100、200、300 毫秒，循环 2 次。点击步骤序号为 `0, 1, 2, 0, 1, 2`，对应界面上的第 1、2、3 步各两轮。这是 M2 的规则，M1 界面只编辑第一步，模拟先把规则钉住。

### 3.4 随机间隔

用种子 `20261018` 抽了 1000 次，区间 400–600 毫秒，含两端。1000 次都在区间内，取值不只一个。M1 界面还没有放开这个选项，规则测试先做了。

## 4. 模拟器上的选点

华为 Mate 40 Pro+（鸿蒙 4.2.0）上，旧包一点「选点」就退出，画面回到桌面。原因是编辑页在还没切到目标应用时就把自己退到后台，前台服务启动失败后进程被杀掉，系统就露出了桌面。

改成：先在应用仍在前台时拉起悬浮球；用户从最近任务切到目标应用；再点圆点里的「选点」，全屏选点层盖在当前应用上。

模拟器：Pixel 6 外观，1080×2400，Android 14。安装本地 debug APK（10,121,093 字节），授予悬浮窗和辅助功能。

| 步骤 | 结果 |
| --- | --- |
| 编辑页点「准备选点」 | 进程号保持 4918，当前页仍是浮序，没有回到桌面 |
| 打开时钟后再点圆点「选点」 | 进程号仍是 4918；前台仍是时钟；出现全屏悬浮层，文案为「点按要记录的位置」，旁边有「取消」 |
| logcat | 没有 `Floatap` 或 `AndroidRuntime` 错误 |

系统设置页会主动藏掉普通悬浮窗，所以选点要在时钟这类普通应用上做，不要在设置页上看圆点。

## 6. 下次在手机上要做的检查

1. 安装 debug APK，阅读使用边界后进入首页。
2. 不授权时，「开始」不可用，设置页能跳到系统授权。
3. 在一个已知界面选点，编辑页能看到坐标和当时的宽高。
4. 间隔 500 毫秒、时长 10 秒，数点击次数是否在 18–21。
5. 运行中点悬浮球或通知里的停止，之后不再点击。
6. 关掉辅助功能后再点开始，不能开始。
